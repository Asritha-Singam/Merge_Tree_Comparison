# Changes: JAR files replaced by .java files

Every `.jar` in this repository has been deleted. Each one still in use has been replaced by a `.java` file with the same name, in the same folder. That file runs directly in Java's single-file source mode (JDK 11+), for example `java -cp CustomisedWasserstein CW-MTED.java <tree1.jt> <tree2.jt> <outdir>`. The jgrapht/jheaps classes come from the existing `CustomisedWasserstein/org/` folder, which is unchanged.

Paths are relative to `Merge_Tree_Comparison/`. `../TreeEditDistanceJavaCodes/` is the reference repository next to this one. It was only read, never modified.

## Verification

For each JAR, the JAR and its `.java` replacement were run on the same inputs and their output compared:

- **Driver runs:** all four Driver runs (the three example makefiles plus an all-pairs run on 8 trees) produced 820 of 821 output files byte-identical, including all plots and `WM*.png` matching images. The one difference is a single Wasserstein value, which differs only in its last floating-point digit (about 1e-16).
- **Bottleneck:** identical on 820 tree pairs.
- **CW-MTED, CO-MTED, CustomisedWasserstein and SeeMatching:** on the same 820 pairs, distances match to within about 1e-15. Where several optimal matchings exist, the chosen one can differ. The original JARs show the same variation when Java is launched differently, because the original code orders some results by Java object hash codes.
- **Error cases:** on bad input (malformed, empty or missing files, too few arguments) the JAR and the `.java` fail with the same exception. On NaN/Infinity values both hang, which was already the case with the original JARs.
- **W1 test:** `test(W1)/test_trees/CustomisedWasserstein.java` matches its JAR on 400 tree pairs (399 identical, 1 differing only in the last digit).

## Undo

Every deleted JAR is still in git history: `git checkout -- <path>.jar` restores it. `git checkout -- TreePair.cpp Utilities.py "test(W1)/test_trees/test.py"` restores the original calls.
