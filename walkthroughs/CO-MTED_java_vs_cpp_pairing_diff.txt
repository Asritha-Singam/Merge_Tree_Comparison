=========================================

RESULT IN SHORT
  - Distances: identical on all 256 examples and 250 w1 pairs.
  - Pairings differ on 27/256 examples and 202/250 w1 pairs.
  - Every differing mapping (Java's and C++'s) costs exactly the distance and is a valid
    mapping, so these are ties: several optimal mappings exist and C++ picks a different one.
  - Unlike CW, Java CO is itself not fully deterministic: on ties its choice depends on
    Java identity hash codes, so it can change with how Java is launched (e.g. Tree1 vs TreeC
    gives "3,3 2,2 1,1" from a bash launch but "3,3 4,4 2,2 1,1" from Python, as in these runs).
    C++ CO gives the same output on every run.

HOW TO READ THE ENTRIES BELOW
  Tree1__TreeC  dist J=217.454546          <- tree pair and Java's distance (C++ is the same)
     forward: java 4 pairs, cpp 3 pairs, rel=sub  java-only=['4,4']  cpp-only=[]
       forward / backward : which map file (forwardmapCO.txt / backwardmapCO.txt)
       java N pairs       : number of node pairs ("id1,id2" lines) in Java's file
       cpp N pairs        : number of node pairs in the C++ file
       java-only          : pairs Java has that C++ does not
       cpp-only           : pairs C++ has that Java does not
       rel (relation of the C++ set to the Java set):
         sub   = C++ is a strict subset of Java   -> C++ left out some pairs
         super = C++ is a strict superset of Java -> C++ added some pairs
         cross = each has pairs the other lacks   -> some pairs swapped
       identical  = same pairs in the same order
       order-only = same pairs, different line order (not a real difference)

  "categories" line per dataset:
       identical / order-only / DIFF : number of tree pairs in each group
       cpp fwd==bwd / java fwd==bwd  : tree pairs where forward and backward files are byte-identical

  "diff kinds" at the end of each dataset: (map, rel, size) -> count, where size is
       size cpp fewer / size cpp more / size same : C++ pair count vs Java pair count
